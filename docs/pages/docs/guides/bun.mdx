# Bun [Ponder runs on Bun]

Ponder is a Bun-native indexing runtime. [Bun](https://bun.sh) is the **only supported runtime**. Node.js is not supported.

Bun also includes a package manager. New apps typically use `bun install`; you can still install with pnpm, npm, or yarn. The process that runs `ponder` must be Bun either way.

## New project

```bash [shell]
bun create ponder
```

`create-ponder` requires Bun. Generated scripts stay as `ponder dev` / `ponder start`. **Do not** add `bun --bun` — that flag was a workaround for the old Node shebang and is no longer needed.

```json [package.json]
{
  "scripts": {
    "dev": "ponder dev",
    "start": "ponder start",
    "codegen": "ponder codegen"
  },
  "engines": {
    "bun": ">=1.4.0"
  }
}
```

Then:

```bash [shell]
bun run dev
```

[Read more](/docs/requirements) in Requirements. Existing Node Ponder apps should follow the [migration guide](/docs/migration-guide).

## Bun-native `ponder start` and `ponder dev`

Under Bun, `ponder start` and `ponder dev` use the Bun-native indexing path by default: they load `ponder.config.ts` and `ponder.schema.ts` with Bun `import()`, resolve `ponder:registry` / `ponder:schema` with a Bun plugin, and run indexing (`createDatabase`, `migrate`, `migrateSync`, then `runOmnichain` or `runMultichain`) without Vite. `--native` and `PONDER_BUN_NATIVE=1` still enable that path explicitly.

To force the classic Vite path:

```bash [shell]
PONDER_USE_VITE=1 ponder start
PONDER_USE_VITE=1 ponder dev
```

`ordering: "experimental_isolated"` is not supported on the native path — set `PONDER_USE_VITE=1`. If the compiled database is Postgres, native `start` / `dev` also start the Bun-native `/v1` HTTP server. `--schema` / `DATABASE_SCHEMA` is required for `ponder start`.

## Bun-native `ponder serve`

`ponder serve` still uses the classic Vite/Hono HTTP API unless you pass `--native` or set `PONDER_BUN_NATIVE=1`. To serve the Bun-native `/v1` stack (`Bun.SQL` + `Bun.serve`, no Vite or Hono) without indexing:

```bash [shell]
# Requires DATABASE_URL
ponder serve --native
# or
PONDER_BUN_NATIVE=1 ponder serve
```

This starts `GET /health`, `GET /v1/status`, readonly `POST /v1/sql`, and `GET /v1/live` SSE, then prints the listen URL. Port and hostname still come from `-p` / `-H` (or `PORT`). `--schema` / `DATABASE_SCHEMA` selects the Postgres schema (`public` by default); invalid identifiers exit with an error. Classic `ponder serve` without `--native` is unchanged.

## Known limitations

If you encounter an issue with Ponder that might be caused by Bun, please [open a GitHub issue](https://github.com/ponder-sh/ponder/issues).

- The `/metrics` endpoint omits the default Node.js Prometheus metrics that `prom-client` used to attach (names prefixed with `nodejs_` or `process_`).
