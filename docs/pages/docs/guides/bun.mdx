# Bun [Ponder runs on Bun]

Ponder is a Bun-native indexing runtime. [Bun](https://bun.sh) is the **only supported runtime**. Node.js is not supported.

Bun is both the **runtime** and the **package manager** for this project (`bun install` / Bun workspaces). New apps typically use `bun install`; `create-ponder` can still scaffold with pnpm, npm, or yarn if you pass `--pnpm` / `--npm` / `--yarn`. The process that runs `ponder` must be Bun either way.

## New project

```bash [shell]
bun create ponder
```

`create-ponder` requires Bun. Generated scripts stay as `ponder dev` / `ponder start`. **Do not** add `bun --bun` — that flag was a workaround for the old Node shebang and is no longer needed.

```json [package.json]
{
  "scripts": {
    "dev": "ponder dev",
    "start": "ponder start",
    "codegen": "ponder codegen"
  },
  "engines": {
    "bun": ">=1.4.0"
  }
}
```

Then:

```bash [shell]
bun run dev
```

[Read more](/docs/requirements) in Requirements. Existing Node Ponder apps should follow the [migration guide](/docs/migration-guide).

## Bun-native `ponder start` and `ponder dev`

Under Bun, `ponder start` and `ponder dev` use the Bun-native indexing path by default: they load `ponder.config.ts` and `ponder.schema.ts` with Bun `import()`, resolve `ponder:registry` / `ponder:schema` with a Bun plugin, and run indexing (`createDatabase`, `migrate`, `migrateSync`, then `runOmnichain` / `runMultichain` / `experimental_isolated`) without Vite. `--native` and `PONDER_BUN_NATIVE=1` still enable that path explicitly.

Postgres indexing uses **Bun.SQL** by default under Bun. Set `PONDER_DATABASE_DRIVER=pg` to force node-postgres.

To force the classic Vite path:

```bash [shell]
PONDER_USE_VITE=1 ponder start
PONDER_USE_VITE=1 ponder dev
```

`ordering: "experimental_isolated"` runs on `Bun.Worker` with the same Vite-free compile path. If the compiled database is Postgres, native `start` / `dev` also start the Bun-native `/v1` HTTP server from the same `createDatabase` connection. `--schema` / `DATABASE_SCHEMA` is required for `ponder start`.

Secondary commands `ponder db list`, `ponder db prune`, and `ponder db create-views` also use the Bun-native compile path under Bun.

## Bun-native `ponder serve`

Under Bun, `ponder serve` defaults to the Bun-native `/v1` stack (`Bun.serve`, no Vite or Hono) unless you set `PONDER_USE_VITE=1`. `--native` and `PONDER_BUN_NATIVE=1` still enable it explicitly.

```bash [shell]
# Requires DATABASE_URL
ponder serve
# or force native
ponder serve --native
```

This starts `GET /health`, `GET /v1/status`, readonly `POST /v1/sql`, and `GET /v1/live` SSE, then prints the listen URL. Port and hostname still come from `-p` / `-H` (or `PORT`). `--schema` / `DATABASE_SCHEMA` selects the Postgres schema (`public` by default); invalid identifiers exit with an error.

```bash [shell]
PONDER_USE_VITE=1 ponder serve
```

## Known limitations

If you encounter an issue with Ponder that might be caused by Bun, please [open a GitHub issue](https://github.com/ponder-sh/ponder/issues).

- The `/metrics` endpoint omits the default Node.js Prometheus metrics that `prom-client` used to attach (names prefixed with `nodejs_` or `process_`).
- Bun.SQL does not expose streaming PostgreSQL `COPY FROM`; large flushes use batched inserts.
- Escape hatches remain: `PONDER_USE_VITE=1`, `PONDER_DATABASE_DRIVER=pg`.
