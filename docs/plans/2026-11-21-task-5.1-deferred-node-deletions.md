# Task 5.1 deferred Node deletions

Removing these in the same commit as the `@hono/node-server` / `pg-copy-streams` / CLI Bun cut would delete the only remaining production indexing path. Bun replacements exist as slices, but they are not yet wired through `ponder start` / `ponder dev`.

## `pg` (node-postgres)

Still the production Postgres client. `Bun.SQL` (`createBunSqlDatabase`) now accepts a `schema` and sets `search_path` / `CREATE SCHEMA` on connect, but it is not the `createDatabase` default — production indexing still uses `pg`.

- `packages/core/src/utils/pg.ts`
- `packages/core/src/database/index.ts`
- `packages/core/src/database/queryBuilder.ts`
- `packages/core/src/database/queryBuilder.test.ts`
- `packages/core/src/database/index.test.ts`
- `packages/core/src/internal/types.ts`
- `packages/core/src/config/index.ts`
- `packages/core/src/client/index.ts`
- `packages/core/src/_test/setup.ts`
- `packages/core/src/_test/globalSetup.ts`
- `simulation-test/src/db-sim.ts`
- `packages/core/package.json` (`pg`, `@types/pg`, `pg-connection-string`)

`pg-copy-streams` is gone. Large Postgres flushes in `packages/core/src/indexing-store/cache.ts` use Drizzle insert / `ON CONFLICT` instead of `COPY FROM STDIN`. PGlite still uses blob `COPY`.

## Vite SSR loader and `ponder:*` virtual modules

`ponder start --native` now loads `ponder.config.ts` / `ponder.schema.ts` with `bunLoader` (`packages/core/src/build/bunLoader.ts`) via Bun `import()`, then optionally starts the Bun `/v1` stack. Classic `ponder start` / `ponder dev` still boot Vite `createServer` + `createServerModuleRunner` and the `ponder:registry` / `ponder:schema` / `ponder:api` plugin. User indexing functions still import those specifiers on the classic path.

- `packages/core/src/build/bunLoader.ts` (`ponder start --native` only)
- `packages/core/src/build/index.ts`
- `packages/core/src/build/plugin.ts`
- `packages/core/src/build/stacktrace.ts`
- `packages/core/src/types.d.ts`
- `packages/core/src/bin/utils/codegen.ts`
- `packages/core/package.json` (`vite`, `./virtual` export)
- examples, templates, simulation-test, and benchmark `ponder-env.d.ts` / `ponder:*` imports

Vite remains the production loader for `ponder dev` and unflagged `ponder start`.

## `worker_threads`

`isolatedController` now spawns workers through `createIndexingWorker` (`packages/core/src/bin/utils/indexingWorker.ts`). Under Bun that factory uses `Bun.Worker` and `isolatedWorker.bun.ts`. That entry only speaks a kill/done handshake; full `runIsolated` (createBuild, database, per-chain ready/done/error, IsolatedMetricsService) is not ported, so isolated indexing still does not run events on the Bun worker.

- `packages/core/src/bin/utils/indexingWorker.ts`
- `packages/core/src/bin/isolatedWorker.bun.ts`
- `packages/core/src/bin/isolatedController.ts`
- `packages/core/src/bin/isolatedWorker.ts`
- `packages/core/src/internal/metrics.ts`
- `packages/core/src/build/index.ts` (`isMainThread`)
- `packages/core/src/runtime/bunIsolatedWorkers.ts` (slice, not the CLI controller)
