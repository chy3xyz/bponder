# Task 5.1 deferred Node deletions

Removing these in the same commit as the `@hono/node-server` / `pg-copy-streams` / CLI Bun cut would delete the only remaining production indexing path. Bun replacements exist as slices, but they are not yet wired through `ponder start` / `ponder dev`.

## `pg` (node-postgres)

Still the production Postgres client. `Bun.SQL` lives in `packages/core/src/database/bunSql.ts` and is not the `createDatabase` default.

- `packages/core/src/utils/pg.ts`
- `packages/core/src/database/index.ts`
- `packages/core/src/database/queryBuilder.ts`
- `packages/core/src/database/queryBuilder.test.ts`
- `packages/core/src/database/index.test.ts`
- `packages/core/src/internal/types.ts`
- `packages/core/src/config/index.ts`
- `packages/core/src/client/index.ts`
- `packages/core/src/_test/setup.ts`
- `packages/core/src/_test/globalSetup.ts`
- `simulation-test/src/db-sim.ts`
- `packages/core/package.json` (`pg`, `@types/pg`, `pg-connection-string`)

`pg-copy-streams` is gone. Large Postgres flushes in `packages/core/src/indexing-store/cache.ts` use Drizzle insert / `ON CONFLICT` instead of `COPY FROM STDIN`. PGlite still uses blob `COPY`.

## Vite SSR loader and `ponder:*` virtual modules

`createBuild` still boots Vite `createServer` + `createServerModuleRunner` and the `ponder:registry` / `ponder:schema` / `ponder:api` plugin. User indexing functions import those specifiers. A Bun `import()` loader is not wired to the CLI.

- `packages/core/src/build/index.ts`
- `packages/core/src/build/plugin.ts`
- `packages/core/src/build/stacktrace.ts`
- `packages/core/src/types.d.ts`
- `packages/core/src/bin/utils/codegen.ts`
- `packages/core/package.json` (`vite`, `./virtual` export)
- examples, templates, simulation-test, and benchmark `ponder-env.d.ts` / `ponder:*` imports

Until a Bun loader lands, `ponder dev` / `ponder start` keep the Vite path.
